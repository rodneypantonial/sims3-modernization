# 294 EA app 1.69 parity: the last unmapped Steam rows

2026-11-20, static only (no game run). Branch `ea169-parity` on public main cf6b7671b + the rc-1119b ini.

**Answer.** 153 of the 216 `// unresolved` rows of `native/ts3native/ts3addr-ea169.h` now have their EA app 1.69.47
address; every one has a two-way match (Steam -> EA and EA -> Steam unique to the same address) and 12 needed an
override because the signature map picked a look-alike or found nothing (`docs/data/ea169-overrides.csv`). The features
those rows held back run on EA: the rc ini plan goes from 7 zeroed sections + 11 zeroed keys to **0 + 0**. Left at 0:
the 63 rows of `gcgate.cpp` ([GC] IdleGate, hold + G2, SubTimers) and `gcmark.cpp` ([GC] MarkHelpers), not part of this
pass; their guards stay. Each section needs one EA correctness run (§5) before it counts as working on EA.

## 1. Method

- Image: the decrypted EA dump rewritten as a file-layout PE (docs/230 §2, `ts3-ea169-file.exe`), Steam ref
  `game-copy/bin/TS3W.exe`. Both read-only.
- Forward: `node tools/port-run.ts --exe <EA file exe> --ref <Steam exe> --allow-inferred --zero-unresolved --table
  native/ts3native/ts3addr-ea169.h --host-name "EA app 1.69.47" --overrides docs/data/ea169-overrides.csv`.
- Back: `node tools/exe-addr-map.ts --ref <EA file exe> --other <Steam exe> --addrs <EA candidates>`: each candidate must
  map back to its own Steam address.
- Code rows: the first 6 instructions are equal with address operands masked (capstone, scratch script); call sites
  call the EA address the table gives their Steam target. This check caught two rows the map called exact or near:
  `0x74A830` (only the 24 bytes *before* it matched, the previous function's tail) and `0x56FA98` (same 80 bytes as
  another site that calls the slot +8 clone of the callee).
- Data rows: xref votes both ways (2 or 3 votes), or for 1-vote rows the structure (vtable slot holds the mapped
  function, getter/setter shape).
- Bytes: the regenerated bytes table has no `bytes-bad` row (before the overrides: 2). Only the target rows were taken
  into the committed tables (a full regen drops 7 address rows and 4 satb bytes rows that `satb.cpp` still reads through
  `g_satbNatAt`): 153 address rows, 63 new bytes rows.

Levels: **[verified]** = unique two-way match plus the instruction/target or slot check above. Every row in §6 is
[verified]; none is left [inferred].
