## Ship rule

A candidate ships only with a positive forced-repro A/B (docs/169/170: same load, switch off vs on, ABBA, fixed event count; hitch counts >= 300 / >= 1000 ms, max, p99) and no crash; crash fixes ship after 2 clean verify runs. Natural-play pairs (docs/RELEASE.md 2026-10-22 table) are regression guards, not evidence for a ship decision. Decided 2026-10-24 from the overnight-1023 queue and the earlier repro runs.

## Measurement notes

- **Void runs found 2026-10-24:** with an asi older than 679efd78 (the prologue read at load), the profiler's task attribution (Frida on `0xEA1090`) rewrote `0xE5A600` before the lazy route worker hook installed: `invokeHook -1`, every plan sync, 0 async jobs, and the jobs PASSed. Affected: `ip-rvb-v014`, `sv-soak-v014` (2026-10-23), `ip-rcr-route-legs`, `sv-route-seacheck-freeze(-ab)` (2026-10-22), `sv-crowd-freeze-cause` (2026-10-23). `queue.ts` now fails a job on any ts3native `FAIL` hook line (pre-run and every 30 s in the run guard) and when `[RouteAsync]` is on but no async job started; old-asi jobs run with `profOpts {"tasks": false}`.
- **Sim iterations per second** are lower with background routing than vanilla (SV ~70-75 vs ~94), level with v0.1.4: the sim waits on the route job's `+0x918` (pump, gate, destroy, discourage drain ~70 ms/s), seen as TaskObjects time. Hitch counts, not iteration rate, are the release metric. Game-minutes per real minute is not measured yet.
- **SV soak (asi.0338 candidate, overnight-1023):** 3 iterations >= 1 s in 45 min (max 2,273 ms), one-to-one with own-START route jobs of 816-2,281 ms with the sim in `WaitAsyncDone`/`WaitJobDone`. Release build vs v0.1.4 on the same seed: Natural play below (v0.1.4 3 >= 1 s, max 1,719 ms; v0.1.5 4, max 3,681 ms; all main-thread `Foreign` sync plans, not own jobs).
