## Publishing a hotfix

`tools/publish-public.ts` (master only; added after v0.1.5) syncs `git archive <ref>` of the checkout it runs from, and the public tag build compiles that tree. Run it from the main checkout with `--ref hotfix/v0.1.6-userdiag`, so the published tree is this branch, not master's unreleased code (0.36.5x):

    node tools/publish-public.ts release v0.1.6 --ref hotfix/v0.1.6-userdiag --native-version 0.36.37a --message-file <msg> --ini .claude/worktrees/hotfix-016/native/ts3native/ts3native.ini --package <tested ts3fixes.package>

Dry run first, `--yes` (with `GH_TOKEN="$PERSONAL_GITHUB_TOKEN"`) only after Rodney's OK. The branch carries 31 files that the post-v0.1.5 public sync (PR #64) added from master (tools, harness queues, skills, docs; copied as they are on public main), so the sync does not delete them; none is built into the asi or the package. Two files of PR #64 stay out: `mods/ts3fixes/src/DisposeSpread.cs` and `SeasonMarkerCache.cs` (build-fixes compiles every `.cs` in that folder, and both need master-only tunables `kDisposeSpread*` / `kSeasonMarkerCache`, so the branch's ts3fixes would no longer build and its source would no longer match the shipped package). Afterwards merge the CHANGELOG section and these notes back into master.
