# 76. Snapshot change hooks: world epoch and destroyed/hidden writers (gap 10a, 10b)

Static map for the incremental autonomy snapshot (docs/59 §3.3: only an incremental native snapshot can break even). Written 2026-10-16 from a Ghidra headless pass on a private copy of the project with our symbol CSV imported, plus a read of the decompiled ScriptCore, SimIFace, Sims3GameplaySystems and UI assemblies. No game run, no probe. Steam 1.67 `TS3W.exe`, image base `0x400000`.

Tags as in AGENTS.md: **[verified]** = read in the disassembly, decompile or managed source; **[inferred]** = reasoning still to confirm (ledger rows I-76-*, docs/51 §10). Rates are estimates until 10e measures them.

## 1. Summary

- **The game already has two native event buses that cover almost every change the snapshot cares about**, so 10a and 10b need one detour and no other code patch:
  1. **Object events** (`GlobalHandlerChain 0x936C90` over the handler lists at `0x11DC2A8`, 42 event ids, registered with `ObjectEvents_Register 0x936BC0(event id, fn, priority)`, cdecl) [verified: the 13 register call sites push those three arguments; the chain calls `fn(object, data)` and stops when a handler returns 0]. A handler of ours is a **list insert, not a code patch**. Relevant ids, from the push operand at each of the 89 dispatch sites [verified]: `4` added to the id hash (`ObjectService_AddObject`), `5`/`6` before/after destroy (`ObjectService_DestroyById`), `0x18` visual-state flags changed (the only writer of the "model visible" bit), `0x0B`/`0x0C` added to / removed from the scene or object manager, `0x0E` transform published (`Transform_Publish 0x959670` and four siblings), `0x21` transform parent changed.
  2. **World events** (`World_FireEvent 0x78F2B0`, 76 call sites, one per `WorldEvent` id, each forwarded to a managed callback in `Sims3.SimIFace.World`) [verified call sites and the managed enum]. Lot added, removed, bounds and type changed, walls/footprint/edit zones changed, world load started/finished, world quit and object lot/room update all pass through this one function.
- **10a (world epoch):** one detour at the entry of `World_FireEvent` (7 bytes `SUB ESP,0x44; MOV EAX,[ESP+0x4C]`, relocatable; not in any docs/68 signature window), plus **IC binding-table slot swaps** for the build/buy boundary (`World_LotClusterTreesImpl`, slot `0x11623B0`, cluster=false on enter and true on exit; `RouteManager_OnExitBuildBuy`, slot `0x1160DA8`). No world event marks build/buy enter or exit, and roof edits fire none, so the build/buy boundary is the roof/outside epoch [verified: managed callers below]. **Lot streaming needs no epoch bump** [inferred, I-76-4]: it moves objects in and out of the scene only (docs/38), touches visual-state mask `0x20`, not the model-visible bit the snapshot reads.
- **10b (destroyed/hidden):** subscribe to object events `6` (destroyed), `0x18` (visual flags), `4` (new object) and `0x0B` (back in the scene after an inventory remove). Together they catch every native and script path found: script `Destroy`, animation prop drain, lot unload, world shutdown, build/buy tools, animation visibility clip events, `RemoveFromWorld`/`AddToWorld`, inventory moves. The **footprint-hidden bit has its own writer with no event** (`0x947590`, our symbol `Locomotion_Notify` is a misnomer, §3.2); it needs a detour only if the snapshot keeps that bit (I-76-9).
- **Managed-only state** (`GameObject.InWorld`, `InInventory`, `Sim.HasBeenDestroyed` via `SimDescription.CreatedSim`) has no native writer. For objects, every managed flip found happens in the same script call as at least one native event for the same id (§3.3) [inferred, I-76-3], so the native subscription covers it; Sims stay always dirty (PLAN gap 10).
- **Avoid** the two obvious detour sites: `ObjectService_DestroyById 0x939420` is owned by `[Verify]` (`rtDestroy`) and planned by docs/60 #4; `RoutingSystem_OnExitBuildBuy 0x835240` is `[Verify]` `rtExitBuildBuy` and planned by docs/60 #7 (docs/68 rule 3).
- **Head start for 10c/10d:** the parent setter fires object event `0x21` (three writers of transform `+0x30`: `0x959FC0`, `0x95A360`, `0x95ABA0`) and every transform publish fires `0x0E`, so both can use the same subscription instead of the detours docs/59 §3.3 assumed. `0x0E` also fires from `RigPose_Update` per animated object per update, so it is the high-rate one [verified call sites; rates inferred].

**Rule for the builder** [design, inferred]: epoch = counter bumped by the dispatcher stub (ids above) and by the build/buy slots; snapshot rows tagged with an older epoch are dropped and the next search does a full rebuild. Houseboat lots and lots with a `TombRoomManager` are always rebuilt in full (no per-move event known). A world load also makes every cached object pointer invalid, so the stub for ids 3/5 must clear the dirty set, not only bump.

Pause note: build/buy, CAS and Edit Town pause the clock; docs/59 §3.5 already pauses the worker for them. If no autonomy search runs inside build/buy (I-76-5), the exit bump alone is enough and enter is a safety bump.

### 3.3 Single site for a dirty bit

**One mechanism, no code patch:** register one handler with `ObjectEvents_Register` for events `4`, `6`, `0x0B` and `0x18` (and later `0x0E`, `0x21` for 10c/10d). The handler reads the object id at `object+0x08`/`+0x0C` (docs/45 §2) and sets the dirty bit or pushes the id into the 10f ring; it returns 1 so the chain continues [design].

Details [verified unless tagged]:
- Registration allocates a 12-byte node `{priority, fn, next}` from the object service allocator and keeps each list sorted by priority, high first; equal priority goes to the tail. Existing handlers use priority 0, so priority 1 puts ours first, before any handler that could return 0 and stop the chain.
- `ObjectEventHandlers_FreeAll 0x936C40` frees every node through the same allocator at `ObjectService_Release 0x938900`, so the node must come from `ObjectEvents_Register`, never from our own memory.
- The lists have no lock. Register from the sim thread between dispatches (for example the first `[Verify]`-style sim tick after the object service exists) [inferred safe: every dispatcher found is on the sim thread, I-76-1].
- Event `0x0C` is not a destroy signal: lot streaming (`Lot_RemoveLotObjectsFromScene 0xAB4C00`) and `Lot_Unload` fire it for every object of a lot, so subscribing to it would flood the dirty set on each activation. Use `6` for destroy.
- A model-hidden object that is then removed from the world fires no `0x18` (bit 0 does not change); its `InWorld` flip is managed only. The snapshot is still right if it reads `InWorld` live (docs/59 §3.4: managed state is read in place while the worker runs) or if `RemoveFromWorld`'s `SetPosition(OutOfWorld)` (`0x0E`) is subscribed too [inferred], I-76-3.
- Bursts (world shutdown `DestroyAll`, lot unload, save clones `ObjectService_CloneObject` <- `Lot_Save`, which fire `4` and `6` per clone) overflow any ring: overflow = full rebuild (10f) [inferred].
- Footprint bit: either drop it from the snapshot row (if no allow-listed `Test` reads `HiddenFlags.Footprint`) or detour `0x947590` at entry (`PUSH EBX; MOV BL,[ESP+8]; PUSH ESI; MOV ESI,ECX`, 9 bytes, not listed in docs/68). Decide after the allow-list scan (12b) and I-76-9.

**Cost** [inferred]: one indirect call and a set insert per event, ~10-30 ns. At the estimated 2-50 events/s for `4`/`6`/`0x0B`/`0x18` that is well under 0.01 ms/s. `0x0E` (10d) is the only id with a high rate.

## 4. Corrections and additions to other docs (not edited here)

- docs/59 §3.3: "Dirty-row tracking needs a hook on the native transform and parent setters, which are not mapped yet": both setters already publish object events (`0x0E` from five transform functions including `Transform_Publish 0x959670`, `0x21` from the three parent writers), so a subscription replaces the hooks [verified call sites; `0x21` = parent change inferred from the `+0x30` write next to the push].
- docs/45 §5 / docs/50 §2 G: two more `DestroyById` callers in the script host: `0xD70B80` (host destroy-object method, vtable entry `0x108B824`, the target of `IC_Simulator_DestroyObjectImpl` [inferred]) and `0xD7BC70` (cleanup when a script create fails); three in the build/buy tool range (`0xD27F50`, `0xCDBD40`, `0xD4C790`).
- docs/50 §1: "`ObjectEvents_Register` ... (event id, fn, 0)" is right; the third argument is a priority that orders the list (§3.3).
- Symbol `Locomotion_Notify 0x947590` (docs/22 row): it is the Footprint component's enable setter (§3.2). Rename when the symbol CSV is next edited.
- New names for the CSV when someone next edits it: `VisualState_SetFlags 0x95FC50`, `VisualState_SetVisible 0x95FCB0` (mask 1), `ScriptHost_DestroyObject 0xD70B80` [inferred], `Footprint_SetEnabled 0x947590`.

## 5. What 10e and 10f need next

- **10e (counters, short game run):** a ts3native handler registered for object events `4`, `6`, `0x0B`, `0x18`, `0x0E`, `0x21` that counts calls per event, per thread role and distinct ids per second (no behaviour change), plus a call/thread counter at the `World_FireEvent` stub by id. One BP and one IP load with the verify sweep plus: eat a meal (plates destroyed), inventory pick-up/put-away, build/buy enter-edit-exit, an Edit Town lot change. Ledger rows I-76-1..9 give the expected values. Also needed from 10c/10d before 10e: whether any position writer bypasses `0x0E`.
- **10f (dirty-set design):** inputs from this doc: the id comes from the object pointer in the handler; burst sources are known (shutdown, lot unload, save clones, build/buy tools), so the ring can be small (the 20-60 rows per search estimate of docs/59 §3.3) with overflow = full rebuild; the epoch from §2 invalidates everything; houseboat and tomb lots are always rebuilt.
- **Registry:** a counter version for the new handler (docs/registry.md) is reserved by the 10e build, not here.
