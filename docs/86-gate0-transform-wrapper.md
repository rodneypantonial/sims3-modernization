# 86. Gate 0 at `0x62EF7A`: the lot transform wrapper `0x62EF30`

Written 2026-10-18. Static only; the game was not run (PLAN "Routing off-thread" item 2, docs/84 §7 item 8). Tools: Ghidra headless decompiles on a private copy of the docs/84 project (`game-copy/ghidra-g0`, copied from `ghidra-w3`, read-only runs), capstone 5 on `game-copy/bin/TS3W.exe` (Steam 1.67) with a raw `E8`/`E9` caller index over `game-copy/analysis/functions.csv`, a reverse walk that marks a `+0x918` acquire before the call in the same function, a 5-hop forward closure over direct calls (flags: `Lock_Acquire 0x4E16F0` with its `ecx` source, `World_FireEvent 0x78F2B0`, `RemoteCall_Dispatch 0x7D98C0`, `ScriptHost_InvokeDelegate 0xD75FA0`, runtime_invoke `0xEA1400`/`0xEA1090`, script message scope `0x7D2DB0`, absolute writes), a `.rdata`/`.data` vtable reference index and the PE import table. Live numbers are re-read from existing runs in `probe-out/queue` (`*-native.json`, after minus before). Scratch scripts stay in the session scratchpad. Script side: `game-copy/decompiled` (grep).

Tags as in AGENTS.md: **[verified]** = read in the disassembly, decompile, source or a run file (address or file given); **[inferred]** = reasoning, to confirm with the §7 probe or the shadow job.

## 1. Summary

- **What the wrapper does [verified, `0x62EF30..0x62EFED`].** `thiscall(P)(lotLo, lotHi, x, z, float* outX, float* outZ)`, `ret 0x18`, `ecx` = lot planner P (`[world+0x95C]`). It calls `LotTable_GetOrInsert 0x62EAB0` on `P+0x48` with the 8-byte lot key (call at `0x62EF75`, return address `0x62EF7A` = the gate-0 key), multiplies `{x, 0, z, 1.0}` (1.0 from `[0x107A538]`) by the four 16-byte rows at entry `+0xA0`, `+0xB0`, `+0xC0`, `+0xD0`, and stores components 0 and 2 to the two out pointers. Nothing else: no lock of its own, no global write, no managed reach (§3). `SrXform` in `native/ts3native/steerro.cpp` is already a bit-exact clone (steerro-test D).
- **The transform reads nothing a job writes** [verified writers, timing inferred]. The matrix rows are written only by the insert copy (`0x62DE40`, from the `LotGraph_ctor 0x62AA60` default) and by `LotTable_InitLotEntry 0x630CF0`, whose callers are `RoutingWorld_RemoveLot 0x829D50` (inside `+0x918`) and `RoutingSystem_RebuildLotRouting 0x835110` (gate site 14). The only job-side hazard is the table itself: a worker `GetOrInsert` miss inserts (`0x62E680`) and may rehash (`0x625940`, frees the old bucket array). So the gate-0 wait is **gate policy, not a data dependency**: the gate waits on any outermost lot-table entry while a job runs.
- **Why it still waits, by caller class [verified order, share inferred].** 16 direct call sites in 9 functions (§2). Two classes reach the sim's wait:
  - **G-a, second touch after a released `+0x918`:** `RouteFollow_A 0x846B70` (after `RoutingWorld_ObstacleQuery 0x82EDB0` at `0x846D1C`), `RouteFollow_B 0x85B470` (after `0x82EDB0` at `0x85B507`), `RouteFollow_EditPath 0x85F5A0` (after `GoalFootprintGather 0x82F0B0` at `0x85F6C6`). When their acquire returns, the job they waited for is over; a job seen at the transform **started in the gap** after the release: `ServeAsync` starts the next queued job as soon as `+0x918` is free and `g_rgOffSimOpen` is 0 (`native/ts3native/ts3native.cpp` `ServeAsync`), and nothing is open on the sim between the release and the transform.
  - **G-b, first touch:** `IC_Route_IsPointObstructedBySim 0x751480`, `0x655880` (`IC_Route_GetObstructionAtWorldOrLotPoint 0x751940`), `IC_RouteManager_RoutingBlockerCheck2d 0x74E110` -> `0x82E340`. The transform is the first routing touch, so it absorbs whatever job runs at entry; un-gating it moves the wait to their next touch (`0x82EDB0`, or `0x631E20` -> `0x62ED40` for the blocker check).
  - Not sim waits: the planner callers (`0x653020`, `0x655880` from `0x6435B0`, `PathPlanner_PlanHierarchical 0x65E0D0`; worker inside the job, excluded by the gate) and the camera controller `0x970200` (main thread [inferred, docs/55]; `vfRtGateOffSim` = 0 in `bp-env-on` and `bp-p0-async` [verified], so the path was not hit off the sim in those runs).
- **Correctness side finding [inferred, order verified].** With the job queue, the G-a callers' unlocked work after the release (plain footprint refcount `+1`/`-1`, footprint vtable calls, point-in-polygon through slot `+0xB8` that may rebuild a level cache, `FootprintRefVec_ReleaseRange 0xAAC090`) can overlap a queued job that started in the gap. The gate-0 wait covers only the part after the transform, and only when the job was already running at the transform. This is the docs/60 "first touch" exclusion rule failing inside one native function, the same kind of gap as docs/84 §7 item 6.
- **Live size [verified run files].** Gate 0 (`0x62EF7A`): `h6-m1 bp-env-on` 734 waits, 6.82 s (11.4 ms/s); `clean-night bp-env-on` 1,052, 6.99 s (11.7 ms/s); `bp-s2-on` 984, 7.23 s; `bp-s2-shadow` 973, 6.98 s; IP 199-246, 3.2-3.7 s (5.3-6.2 ms/s). Mean wait 6.6 ms against a mean job of 5.1 ms (`asyncUs`/`asyncStarted`, clean `bp-env-on`) and 10.7 ms at the steering key `0x85FE10`, as expected when the wait starts right after a job starts [inferred]. P0 (`bp-p0-async`, 0.11.4) has no gate-0 wait at all and 141 job-live gate-0 entries (`rgJob_lotTableFind`) against 1,063 in clean `bp-env-on`.
- **Recommendation: design H2, a locomotion-pass start window (§5).** Publish `g_rgOffSimOpen` around the one call of `Locomotion_Update 0x83CED0` (`0xD81C5C` in `MonoScriptHost_Simulate`) so no queued job starts during the steering pass; a job already running at pass entry is still waited for once at the first steering touch. It removes the G-a gate-0 waits inside the pass and, with them, the "started during the pass" part of the other steering keys, and closes the overlap above. No game code is cloned. **Gain cap** 11.4 ms/s for gate 0 itself; across all steering keys at most ~40 ms/s (clean `bp-env-on`: `0x85FE10` 19.7, `0x62EF7A` 11.7, `0x846D21` 8.9 ms/s); realistic **3-10 ms/s** net, since held jobs then meet the later stages' routing touches [inferred]. **Effort ~2 days.** P1b (built, `bp-p1b`) gives the per-caller split first.

## 5. Design options

Rules as in docs/80/83/84: sync reads the sim needs now cannot move to the worker; lock-free only where no job-written state is read; managed reach stays on the sim; gains do not add.

| # | Option | What | Risk | Effort | Gain cap [inferred] |
|---|---|---|---|---|---|
| R | **Lock-free read** (QL shared, `SrEntry` + `SrXform` for callers keyed `0x62EF7A`) | the transform without the gate when QL shared is free and the lot hits | the transform is safe under QL (W5 covers insert and rehash), but it **removes the guard** for what the callers do next: G-a's footprint loop and refcounts, G-b's `0x631E20` portal cache, footprint gather and physics range query, all unlocked, would then run against a job. | S | **Snapshot answer** (docs/80 option 2: per-lot copy of `entry+0xA0..+0xDF`, refreshed when no job runs) | same as R without QL | same guard problem as R; invalidation needs `0x630CF0` and lot insert/remove hooks | 1 d | as R |
| Q | **Queue to the worker** | - | class (a) sync reads feeding steering and script results now; callers read the object model (sim-only) | - | not applicable |
| H1 | **Defer the worker, caller scope**: a frame that publishes `g_rgOffSimOpen` from the prologue of `RouteFollow_A 0x846B70`, `RouteFollow_B 0x85B470`, `RouteFollow_EditPath 0x85F5A0` to their return (all `55 8B EC 83 E4 F0`, plain `ret`, cdecl) | no job starts inside the caller; a job running at entry is met at its `+0x918` acquire as today | small; framing `0x85F5A0` again needs the docs/85 caution (the 0.11.5 freeze is shown not to need the frame, H7 open, weakened) and the `profile-world` clock guard | 1 d | gate-0 G-a share (≤ 11.4 ms/s) moves to the next steering touch in the pass, so ~0-2 ms/s net; value: one wait per call and no overlap of the caller's unlocked reads with a job |
| **H2** | **Defer the worker, pass scope (recommended)**: retarget the `E8` at `0xD81C5C` (bytes `E8 6F B2 AB FF`) to a thunk that raises a window count, calls `0x83CED0` with the same `ecx` and float, drops the count | no queued job starts during the whole locomotion pass; ServeAsync's existing start rule already reads the count | (1) a collect inside the pass (`WaitJobDone`/`WaitAsyncDone` waits for queued jobs) would deadlock: the window must be suspended on that thread before any such wait (rule + counter; no direct managed reach of `Locomotion_Update` within 5 hops, vtable calls not followed); (2) job start latency grows by the pass length (`Locomotion_Update` ~2.4% of sim samples, about 0.5 ms per iteration [inferred]); (3) the worker spins `Sleep(0)` during the pass; (4) frames left by a longjmp: drop the count in the thunk's own SEH and in `RgDrop`-style cleanup | 1.5-2 d (thunk, suspend rule, counters, selftest, steerro-test section, docs/68) | gate 0 ≤ 11.4 ms/s; all steering keys ≤ ~40 ms/s; realistic 3-10 ms/s (held jobs meet the script stage's touches: destroys `0x2000003`, `UpdateSimFootprint 0x833593`) |

**Recommended: H2 first, then H1 only for the script-IC entries of the G-a callers** (second frames `0x74C8AE`/`0x74C99B` into `RouteFollow_A`, `0x85FFC7` into EditPath via `0x85FF30`) if P1b gives them a share, and C only if P1b ranks G-b high. H2 composes with S2 (S2 still answers while a job that started before the pass holds the lock) and with D, L1 and C-A (no new lock, no QL use).

H2 details:
- Window count separate from `g_rgOffSimOpen` users that wait (`g_g0Win`, read by `ServeAsync` next to `g_rgOffSimOpen`), so the counters can tell the two apart and the suspend rule can clear only ours: `t_g0WinSuspend` set by `WaitJobDone`, `WaitAsyncDone` and `RtWaitJob` on the owner thread while the window is up; restored on return.
- Only when `[RouteGate] Enforce=1` and async on; sim thread only (the call site is in Simulate); nesting not possible (single call site) but guarded.
- Switch `[LocoWindow] Enabled=0 Mode=0|1`; runtime mode for `--ab locowin`. Mode 0: count only.
- Counters (reserve in docs/registry.md): `g0wPasses`, `g0wPassUs` (sum, max), `g0wJobStartInPass` (Mode 0: jobs that started while the sim was inside; Mode 1: must be 0), `g0wRunningAtEntry`, `g0wHoldUs` (worker start delay caused), `g0wSuspend` (collect inside the pass), `g0wGate0InPass` (gate-0 waits inside the pass, by P1b second frame).
- Tripwire: `g0wSuspend` > 0 logs the return address once; a window open longer than 250 ms logs and drops itself (watchdog rule).

## 6. Offline proof (steerro-test style) and live shadow job

Offline, before any game run:
1. **steerro-test section H (new):** map TS3W.exe as the other sections; check the bytes at `0xD81C5C` and install the H2 thunk on the mapped call; replace the mapped `0x83CED0` with a fake pass that runs the game's own `RouteFollow_A 0x846B70` and `RoutingWorld_ObstacleQuery 0x82EDB0` over the existing fake lots, tables and footprints (section A world) for N fake Sims. A "worker" thread runs the real `ServeAsync` loop with a fake `g_icPlanOrig` (sleeps 1-8 ms, inserts a new lot through the W5 stub now and then). Assertions: (a) Mode 1: no job reaches `J_RUNNING` between thunk entry and exit unless it was running at entry (`g0wJobStartInPass` = 0); (b) a job running at entry gives exactly one wait, at the first `0x82EDB0`; (c) the answers of the game's `RouteFollow_A` are identical with the thunk on and off (pure scheduling); (d) a fake collect (`WaitJobDone` on a queued job) inside the pass completes through the suspend rule, 0 watchdogs; (e) after the run `g_rgOffSimOpen == 0` and `g_g0Win == 0` (as section E asserts); (f) Mode 0 counts the jobs that (a) prevents.
2. **selftest:** `TestRouteEnforce` extension with fakes for the thunk's convention (ecx and the float passed through, `ret 4`), the suspend rule and the 250 ms self-drop.
3. **tools/emu spec** `loco_window_thunk.py`: the thunk as built against a stub `0x83CED0` that records `ecx`, the float and `esp`; flags and x87 state preserved.
4. `node tools/hook-sites.ts --check` with `0xD81C5C` in docs/68 (no existing hook there [verified docs/68 grep]); `node tools/check-docs-code.ts`.

Live, in `queues/clean-night.json` only (clean machine):
1. **`bp-p1b` / `ip-p1b`** (already queued, 0.14.0): read gate-0 second frames against the §2 table. Decides G-a vs G-b and whether H1/C matter.
2. **`bp-g0w-shadow`** (H2 Mode 0, async + queue + D, seeded BP, 10 min): `g0wJobStartInPass`, `g0wRunningAtEntry`, `g0wPassUs`, `g0wSuspend`. Pass: game alive, 0 watchdogs, clock guard ok, `g0wSuspend` = 0, and `g0wJobStartInPass` > 0 (otherwise H2 has nothing to remove).
3. **`bp-g0w-ab` and `ip-g0w-ab`** (in-load `--ab locowin`, bundle rule): Mode 1 halves `g0wJobStartInPass` = 0, gate-0 waits from G-a second frames near 0, total sim wait (`blockUs` sum) and iterations/s against the Mode 0 halves, `g0wHoldUs` per job under 1 ms, 0 stuck Sims (log only). Re-run P0 after (gains do not add).

## 9. H2 as built (2026-10-18; built, not run)

`native/ts3native/locowin.cpp`, ts3native **0.19.0**, counters **v37** (docs/registry.md), `[LocoWindow] Enabled=0 Mode=1`, runtime switch `g0wMode` (+0x13E8, `--ab locowin`). **Site [verified, capstone on `game-copy/bin/TS3W.exe`].** The call at `0xD81C5C` is preceded by `fld [esp+58h]; push ecx; fstp [esp]` (the dt float, popped from x87 before the call), `ecx = [0x11D9140]` tested non-null. `Locomotion_Update 0x83CED0` reads only `ecx` and `[ebp+8]` at entry (`eax` is zeroed first, `edx` written before any read), has one `ret 4` at `0x83D383`, and the caller's next instruction reloads `ecx`, so no register, flag or x87 result is used. **Window.** The thunk (`__fastcall(self, edx, float)`, the same stack contract) sets `g_g0wIn` (both modes) and, in Mode 1, `g_g0Win`, then reads `g_async.state` (`g0wRunningAtEntry`). `ServeAsync` publishes `A_RUNNING`, then reads `g_g0Win` next to `g_rgOffSimOpen` and backs off (same Dekker order).
