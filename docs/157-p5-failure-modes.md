# 157. P5 / P5b / P5c failure modes and fault injection

Date 2026-10-22. Static read of `native/ts3native/p5.cpp`, `p5b.cpp`, `p5c.cpp`, `p4.cpp`, `p4clone.cpp`, `replay.cpp` and the routing call path in `ts3native.cpp`, plus new selftests; no game run. Ledger §244. Background: docs/94 §19-§22 (P5 refusals, lazy stop, faults, tripwires, nr skew, mod guard M2-1..M2-3, VerifyEvery, P5b/P5c windows), docs/88 design G, docs/67 §10 (crash H) and §11 (crash I).

Question: in how many ways can Mode=2 (P5), the lent lock (P5b, `ReleaseLock=1`) and FreeLock (P5c) fail in a live game, where is each failure caught, what does the code do then, and does a test prove it.

Result: 21 failure modes. Before this work 8 had no test of their recovery path. Now all 8 are covered: by fault-injection hooks in a test-only build (`TS3N_FAULTINJ`, §2) and by new selftests. No real bug found. Three open risks remain, all by design: §3.

Line numbers are the ones on this branch.

## 2. Fault injection (`TS3N_FAULTINJ`)

Test builds only. `selftest.cpp` defines it before including `ts3native.cpp`; a live probe build sets `CL=/DTS3N_FAULTINJ`. A release `ts3native.asi` contains none of it (build.cmd's release line has no define).

- `p4.cpp`: `FI_*` bits and state near `P4CloneAcquire`; `FI_OOM` turns a granted acquire into a copy failure (released to the provider, `P4_AB_MAT`); `FiInRun` (after `P4EaHeapUnlock`) runs inside `P4Guarded`'s `__try` on the worker in a Mode=2 clone run, with the P5b / P5c window open if the job lends: `FI_MANAGED` (`P4Abort(P4_AB_MANAGED)`), `FI_AV` (write through NULL; with `FI_EAHEAP` first enters EA's heap lock `[0x11CB864]+0x4E4` and bumps its depth word, crash H's shape), and selftest-only `FI_STALE` (a recorded write after the cut), `FI_CLOSE` (`rtClosing` set), `FI_BUDGET` (records `t_budget.on` in the run).
- `p5.cpp`: `P5Plan` picks the bits per plan: every `FaultInjectEvery`-th armed Mode=2 plan injects the next bit of `FaultInject` in turn (`FI_EAHEAP` only modifies `FI_AV`), log `FaultInject: Mode=2 plan ... injects 0x..`; a bit the plan never reached is dropped at its end. `ApplyP5` reads `[RouteSnap] FaultInject` masked to the live-safe bits 1, 2, 4, 8 (OOM, managed, AV, EA heap) and `FaultInjectEvery` (default 10). `FI_STALE` and `FI_CLOSE` change shared state (`g_spWrites` without a record, the real closing flag), so live builds never read them.

Selftests (all in the normal selftest run):

- `TestP5` (single thread, P5b off): 64 `FI_OOM` jobs in a row, each released to the provider with no flags and answered by the game, Mode=2 still on; `FI_BUDGET` with a past FbJobCapMs deadline on the thread: `t_budget.on` 0 in the clone run, answer taken.
- `TestP5Fault` (p5fault-test.h, threaded, in `TestP5b`'s fake world: real `CRITICAL_SECTION` `+0x918`, `P5bWorker`, the sim taking the lent lock as steering in every open window): F1 AV in a P5b window, F2 AV with the EA heap lock in a P5c window, F3 three managed tripwires in P5c windows, F4 world close mid-run, F5 a 2.3 s steering holder. Every job: no hang (8 s limit), an answer in the route's list, window closed, `g_p5bIn` 0, `g_p5cJob` 0, the worker owning `+0x918` at the IC's tail, frame object intact (`P5bWorker` checks).

Day verify queue `tools/harness/queues/p5-fault-verify.json` (not run): `bp-p5-fault-trip` (`FaultInject=3` every 10: managed / OOM alternating, third tripwire turns Mode=2 off) and `bp-p5-fault-av` (`FaultInject=12` every 20: one AV holding the EA heap lock in a lent P5c window, P4 off, the game runs on). 5 min each, noisy machine OK, pass rules in the job notes. Needs `game-copy/ts3native.asi.faultinj` (build steps in the queue note).

## 3. Open risks (by design, not fixed here)

1. **Retake watchdog has no escalation** (row 11). An admitted holder that blocks on the job through a wait site that is not routed through `P5cHandBegin` would hang the worker with a `P5b: worker waited` line every 2 s. Known wait sites are covered (row 14); a new one added later would not be. Mitigation today: the queues stop on that log line. A timeout (hand the job to the game's plan and turn P5b off) needs a way to abandon the clone run's frame while the holder still runs: design only.
2. **Refusal storm cost** (row 9). Each refused job can spend up to `kPcWaitMs` (50 ms) in the acquire; with the lock not lent early (`PcAcquireOwnOnly` false) that is under the job's `+0x918`, so the sim waits too. Correctness holds (every request answered); a breaker (Mode=2 off after N refusals in a row) would trade it for coverage. Read `m2Fb` mat share in the verify runs first (p5-bundle-verify passes at mat <= 5%).
3. **`HeapCreate` failure** [inferred, not tested]: `RpAlloc` (replay.cpp:93) calls `HeapAlloc` with a NULL heap if `HeapCreate` failed. The `PcAcquire` copy path is inside `__try` (refused as `PS_COPY`), consumer paths count `rpFaults`, but a call outside a guard would fault. Only under address-space exhaustion, which takes the game down first.
