# Registry: counter slots and ts3native counter versions

Shared numbers that two PRs must never both take. Test tools, logs and results files refer to them, so a number is never reused or renumbered, even after its fix is removed.

## Reserving

`node tools/registry.ts reserve fixes <n-slots> --by <who> --what <text>` (or `reserve native <n-int32> ...`) takes a lock file next to the main checkout's `docs/registry.md`, reads the highest slot / version / offset from this worktree's and the main checkout's `docs/registry.md` **and** from `docs/data/registry-reservations.json` in the main checkout (found through `git rev-parse --git-common-dir`, so parallel worktrees that have not merged yet see each other), prints the range, records it in that file and adds a `reserved (<who>, <id>)` row plus a recomputed next-free row here. `list` shows the reservations and any number taken twice, `release <id>` drops one (a released top range is free again), `fix-next <file>` recomputes the next-free rows (`tools/agent-merge.cjs` runs it after merging this file), `--self-check` runs 12 concurrent reserves against a fixture.

## Rule

1. Reserve before you code with `tools/registry.ts` (above), and name the range in your issue comment.
2. Keep the `reserved` row in your PR; change it to the final meaning before merge.
3. Two PRs that reserved the same number: the first merged keeps it, the other rebases onto the next free one.
4. Gaps stay gaps (slots 19-20): old logs and results already read them as zero.
