# 79. Snapshot change hooks: parent and position writers (gap 10c, 10d)

Static map for the incremental autonomy snapshot (docs/59 §3.3), following docs/76 (10a world epoch, 10b destroyed/hidden). Written 2026-10-16 from Ghidra headless passes on a private copy of the project with our symbol CSV imported, plus a read of the decompiled ScriptCore, SimIFace and Sims3GameplaySystems assemblies. No game run, no probe. Steam 1.67 `TS3W.exe`, image base `0x400000`.

Tags as in AGENTS.md: **[verified]** = read in the disassembly, decompile or managed source; **[inferred]** = reasoning still to confirm (ledger rows I-79-*, docs/51 §11). Rates are estimates until 10e measures them. Function names in §2 are new working names (not yet in the symbol CSV).

## 1. Summary

- **Verdict: 10c and 10d can be a pure event subscription, no detour and no code patch.** The handler of docs/76 §3.3 (one node per event id through `ObjectEvents_Register 0x936BC0`) needs three more ids: `0x21` (parent changed), `0x0E` (transform published) and **`0x12` (the parent of this object moved)**. Event `0x12` is the piece docs/76 did not have: the Slot component's own `0x0E` handler re-fires it once for every direct slot child of the moved object [verified], and no native code subscribes to it today, so its list is empty [verified: the 13 register call sites register 0, 1, 2, 7, 0x0E, 0x13, 0x18 (Slot) and 0, 1, 2, 7, 0x1A, 0x1C (Sim), as docs/50 §1 says].
- **10c (parent):** the transform component's parent field `+0x30` has exactly three writers and each fires `0x21` right next to the write: attach `0x95A360`, detach `0x959FC0`, and the post-load link resolver `0x95ABA0` [verified]. Every native and script path found (script `ParentToSlot`/`UnParent`, carry, animation prop clip events, SACS rig set, routing/vehicle attach `0x84C3B0`, build/buy tools, auto-destroy effects, load) reaches one of the three [verified call trees]. **No bypass.** Inventory "parenting" is managed only and already unparents through `0x21` (docs/76 §3.2).
- **10d (position, non-Sim):** every function that writes the local transform (`+0x10` rotation, `+0x20` position) funnels into one of five publishers that fire `0x0E` (§2.2) [verified]. Script `SetPosition`/`SetForward`/`SetRotation`/`SetTransform`, animation root motion (`RigPose_Update`), steering agents (bicycle, paddleboat), swarm effects, social footprints, build/buy hand tools and lot placement all go through them [verified call trees]. The game has no physics integrator that moves objects (docs/33) [verified there].
- **What the events do not cover (no detour needed, handled in our code):**
  1. **Grandchildren.** World position is composed at read time from the parent chain (`0x958EE0` -> `0x958560` -> parent slot matrix through the slot's virtuals) [verified], so a moved object changes the world position of its whole subtree. The game fires `0x12` only for direct children and nothing re-fires down the tree [verified: no `0x12` subscriber]. Our handler must walk the subtree itself (from our own parent index, built from `0x21`) or mark rows with a non-zero parent as "recompute from the root at build" [design].
  2. **Children of animated bone slots.** A bone pose change moves objects attached to that bone without any event: `RigPose_Update` publishes only the root (`Transform_Publish`), and the bone matrix is read live through the slot [verified the root-only publish; bone-slot read inferred]. For Sim parents (carry, held props, babies, Sims in vehicles) the rule "Sims are always dirty" extends to **every object whose root parent is a Sim**. Non-Sim objects with props on animated bones are rare; mark those always dirty too [design, I-79-4].
  3. **Publish suppressed while a lot loads.** Flag bit 2 at transform `+0x34` skips the `0x0E` dispatch. Its only writer `0x9574C0` is called from the lot object-layer load (`0xAB5130` <- `Lot_LoadObjectLayer 0xACE0D0`) and from `0xAB4FD0` (<- `0xACBE00` <- `0xAD5E50` <- `IC_DownloadContent_StoreLotContentsImpl`, the lot library export) [verified]. Both run inside world/lot load or Edit Town, which bump the docs/76 world epoch (full rebuild) [inferred: whether `0xAB4FD0` clears the bit before return is not read, I-79-3].
  4. **Detach without re-placement.** Detach `0x959FC0` fires `0x21` but no `0x0E`; the IC path re-sets the old world transform right after (so `0x0E` fires), the animation, SACS, build/buy and auto-destroy-effect detach callers do not [verified]. The object itself is dirty from `0x21`; its children need the subtree walk of item 1 [design].
- **Rates [inferred, I-79-5]:** `0x0E` is dominated by Sims (root motion per animation update while they move, ~100-600/s with 8-20 active Sims); non-Sim `0x0E` ~1-30/s in live play (script placement, vehicles while driving, swarm effects), bursts in build/buy (hand tool follows the cursor; clock paused). `0x12` follows the `0x0E` rate of objects that have slot children (Sims carrying, moved tables): ~10-200/s. `0x21` follows prop and carry attach/detach: ~1-20/s. A first test in the handler drops Sims: object `+0x2C` component mask AND `g_CompBit_Sim` (the same test `RigPose_Update` uses) [verified pattern]. Handler cost at ~600 events/s and ~10-30 ns each: ~0.01-0.02 ms/s.
- **What still needs a hook or a full rebuild:** nothing for parent or position. Full rebuild stays only where docs/76 already put it: world epoch bumps (load, travel, Edit Town, build/buy exit), houseboat lots (I-76-8) and dirty-set overflow (10f). The footprint-enabled bit (`0x947590`, docs/76 I-76-9) is the only snapshot field that would still need a detour.

## 2. The transform component

### 2.1 Layout (component bit `0x1`, 0x40 bytes, docs/45 §3)

| Offset | Field | Evidence |
|---|---|---|
| `+0x04` | owner object | [verified: every publisher passes it to the chain as the event object] |
| `+0x10` | local rotation (quaternion, 16 bytes) | [verified: read by `0x958EE0`, compared and written by the setters] |
| `+0x20` | local position (16 bytes) | [verified] |
| `+0x30` | parent object (0 = root; then local = world) | [verified: `0x958EE0` returns the local values when it is 0] |
| `+0x34` | flags: bit 0 animation-driven (`0x959170`, from `RigPose_Update`), bit 1 render resync pending (`0x9574A0`, detach), bit 2 publish suppressed (`0x9574C0`), bit 4 (`0x9574E0`, lot code) | [verified writers; bit meanings inferred from the callers] |

World transform: `0x958EE0` (new name `Transform_GetWorld`) composes the local transform with `0x958560` (`Transform_GetParentWorld`), which asks the parent's slot for its matrix through the slot object's virtuals `+0x14`/`+0x18`/`+0x1C` and recurses through the parent's own transform [verified]. Nothing is cached per child, so a child's world position is always current and never published when only an ancestor moves [verified: no write to a child in the publishers].

### 2.3 The `0x12` child notification

The Slot component registers `0x953030` for `0x0E`. For an object with a Slot component it walks the child list at slot `+0x48` (`0x952F80`, iterator `0x9524F0`) and fires `0x12` with each child object, data 0 [verified]. It runs inside the same `0x0E` dispatch, so a handler of ours with priority 1 sees the parent's `0x0E` first and then one `0x12` per direct child. Children of children get nothing: no handler re-publishes a child's transform [verified]. Attach and the IC detach path publish `0x0E` for the moved object, so its direct children get `0x12` there too; the bare detach `0x959FC0` does not [verified].

## 4. What 10e and 10f need

- **10e counters:** add ids `0x12` to the docs/76 §5 handler list (now `4`, `6`, `0x0B`, `0x0E`, `0x12`, `0x18`, `0x21`), counted per thread role, split into Sim / non-Sim (component mask test) and, for `0x12`, by whether the parent is a Sim. Repros in addition to docs/76 §5: a Sim carrying a plate across the room (expect `0x12` for the plate, nothing for anything on the plate), a table with a vase moved in buy mode (`0x0E` table, `0x12` vase), a Sim boarding a bicycle or boat (`0x21` then `0x12` per move for the rider). Ledger I-79-1..7.
- **10f dirty set:** besides the per-object bit or id ring of docs/76, keep a parent index (child -> parent from `0x21`, children per parent) inside the snapshot table, so a dirty object also dirties its subtree without reading game memory in the handler. Rows whose root parent is a Sim are always rebuilt, like Sims. A parent change of a row with children dirties the subtree. Overflow and epoch rules as in docs/76 §5.
- **Registry:** no new counter slot here; the 10e build reserves its counter version (docs/registry.md).

## 5. Corrections to other docs (not edited here)

- docs/76 §1 "Head start for 10c/10d" and §4: right that `0x0E` and `0x21` cover the direct writers; add that a moved object's descendants are not covered by `0x0E`, only direct children by `0x12`, and that `0x0E` can be suppressed (bit 2) during lot object-layer load.
- docs/59 §3.3 "Dirty-row tracking needs a hook on the native transform and parent setters": no hook; three event ids plus our own subtree walk (this doc).
- docs/50 §1 lists the Slot component's registrations; their handlers are `0x952EE0` (events 0, 7, 1, 2), `0x952F10` (0x13), `0x953030` (0x0E, child notify, §2.3) and `0x953060` (0x18); the Sim component's are `0x950D70` (0, 7, 1, 2), `0x950910` (0x1A), `0x950940` (0x1C) [verified push operands].
- Symbol CSV, when next edited: the names in §2.2, plus `Slot_OnParentPublished 0x953030`, `Slot_NotifyChildren 0x952F80`, `Transform_GetWorld 0x958EE0`, `Transform_GetParentWorld 0x958560`, `Transform_SetPublishSuppressed 0x9574C0`.
