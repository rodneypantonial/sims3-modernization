# 192. Static script-leak scan (docs/191 step 1)

Status: built and run 2026-10-25, static only (no game run). Tool `tools/script-leak-scan.ts`, output `docs/data/script-leak-candidates.csv`. Plan: docs/191 step 1 and its "Changes to the steps" (check subscriptions added in `OnWorldLoadFinished` / `OnStartupApp` / pre-load without a removal, ErrorTrap's per-load delegate note, docs/184).

## 1. Method

`node tools/script-leak-scan.ts [--asm game-copy/assemblies] [--csv docs/data/script-leak-candidates.csv] [--top N] [--no-mods]`; `--self-check` runs a synthetic fixture (no game files).

- **Input.** The 10 EA script assemblies in `game-copy/assemblies` plus every S3SA assembly in the Steam install, `Documents\...\Mods`, `DCCache` and `DCBackup`, read read-only the way docs/132 does (header, index and S3SA entries only; `s3saImages` moved to `tools/extract-assemblies.ts` and shared with `offload-override-scan.ts`). A mod's own copy of a game module (ErrorTrap's `ScriptCore`, simler90's `Sims3GameplaySystems`/`Sims3GameplayObjects`) is skipped and the game's is scanned. Identical images are counted once.
- **IL model.** `tools/managed-callgraph.ts` (docs/78) loads the metadata. New export `methodIl(gi)` returns every instruction plus each instance call site with the instruction that pushed its receiver (the docs/127 stack walk, now per site; `receiverTypes` is built on it unchanged, self-check passes on the real assemblies).
- **Facts per method.** (a) BCL collection calls (`Add`, `Insert`, `Push`, `Enqueue`, indexer set, ... / `Remove*`, `Clear`, `Pop`, `Dequeue`, ... / `ContainsKey`, `TryGetValue`, `Contains`, `Count` as probes) whose receiver is a static field, an instance field, or `field[key]` (inner collection); `ldsflda` + `Array.Resize` = grown by copy. (b) Field stores (`null`, `new`, other value). (c) Delegate subscriptions: `Delegate.Combine`/`Remove` into a field, and `add_X`/`remove_X` calls mapped to the event's backing field through the accessor body; the handler is the `ldftn` right before. (d) `EventTracker.AddListener`/`RemoveListener` per type family. (e) `AlarmManager.AddAlarm*` with the returned handle dropped (`pop`).
- **Triggers.** Forward reach over direct calls, 4 hops, from root sets: per load (handlers registered on `World` load events, methods named `OnWorldLoadFinished`, `OnPreLoad`, `OnLoad`, `PostLoad`, ...), once per app (`.cctor`, `OnStartupApp` handlers), quit (`OnWorldQuit`, quit handlers, `Cleanup`), per interaction (`Run` of `InteractionInstance` subclasses), per object (`OnStartup`, `OnCreation`, `.ctor` of `GameObject`/`SimDescription`), per event (`AddListener` handlers), per alarm (alarm callbacks). The most frequent reachable trigger is reported.
- **Rules.** Static collection (or instance collection of a singleton type: a static field of its own type named `*Instance*`/`*Singleton*`) with adds and no remove, clear or reset (a `null`/`new` store outside the initialiser and outside the adding method). `dead-remove`: every clear sits in a method with no inbound reference, no override slot and no trigger. Delegates: a handler added to a static field, or to an event reached through a static receiver (`Responder.Instance`), with no `-=` of the same handler and no `null` store of the field; instance delegate fields only when re-added on load. Adds only in `.cctor`/app start are skipped (bounded). Lowered confidence: memo patterns (add after a probe, indexer only), adds right after a `new` of the same field in the same method (fill-once or rebuild), adding method behind a static `bool` once-flag, reads that escape (field passed on or aliased).
- **Score** = confidence (3/2/1) x trigger weight (interaction 5, event/alarm 4, object/load 3, unknown 1.5, app 1) x 1.2 for statics x 1.3 for world references. A ranking aid, not a size.

## 4. False-positive classes

1. **Memo and parse caches** (add after `ContainsKey`/`TryGetValue`/`Contains`/`Count`, indexer set only): bounded by distinct keys. Rated medium.
2. **Guard on another field** (`Jukebox.SongData` fills `sDisplayNameToDataMap` only when `sAllSongs` is empty; `Recipe.IntroRecipes` only when `NameToRecipeHash` lacks the key) [verified decompiled]: invisible to a per-field rule, still rated high in the CSV.
3. **Static bool once-flags** (ts3fixes probes): detected (method reads and writes one static bool), rated low.
4. **Fill-once lazy init or rebuild** (`RabbitHole.AttendClassInRabbitHole.sAttendableClasses`, `DynamicChallengeManager` test lists) [verified decompiled]: detected as an add after a `new` of the same field, rated low; a lazy init that keeps accumulating looks the same and is also rated low.
5. **Aliasing and helpers:** a collection copied to a local or passed to a helper that clears it is counted as "reads escape" but its clear is not seen.
6. **Trigger smear:** "per interaction run" means "reachable from some interaction `Run` within 4 direct calls", not "every run". Virtual dispatch is not followed (overrides are roots by name only).
7. **Removal the IL cannot show:** reflection (NRaas option classes), ErrorTrap's `DereferenceDelegate` dropping duplicate invocations at load (docs/184), native resets, or `World` handlers cleared by an engine path we do not see.
8. **Handler identity by method name:** two adds of the same instance method on different objects count as one handler; anonymous methods and lambdas get unique names, so a lambda add has no matching removal by construction (a real "cannot unsubscribe", not an FP).
9. **Short-lived owners:** instance events on UI windows and objects are excluded unless the receiver is static; listeners and repeating alarms end with their Sim/object or the world, so those rows are low.
10. **World-ref statics** pin one graph; bounded, but relevant for world-switch leftovers.

## 6. Limits and next steps

- Static only: no candidate here is a measured leak. #1-#5 are verified as "added and never removed"; their memory size is small per add (delegates, pinned objects) and their CPU cost grows per load. The repros in §5 decide the order.
- Not covered: custom (non-BCL) collection types, caches held in instance fields of non-singleton long-lived objects, collections reached through properties or locals, and native-backed managed wrappers (docs/191 TS3VASManager finalizer claim, step 6).
- Ownership (docs/191): EA store-object and placement subscriptions are game bugs we can fix in ts3fixes (remove before add, or remove in `OnDestroy`/`Cleanup`); NRaas rows go upstream as patches (docs/184 rules, no copied code).
